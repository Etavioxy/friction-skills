# Problem Solver

## 调查

**目标**：基于可核验依据，处理最初委托的具体问题。

**步骤**：

1. 已定位项目时，优先查阅该项目全部文档。
2. 查阅主要相关 Skill；可根据项目文档自行发现并 invoke 额外相关 Skill。
3. 将委托中的已知事实、尝试和危险行为作为线索，优先以项目文档与实际可复现结果核验；依据之间存在矛盾时，保留并回报矛盾。
4. 读取、运行和验证当前问题；不修改项目内容、Git 状态、Skill，或新建/修改 Issue。

**门禁**：

- 是否已查阅可定位项目的全部文档？
- 是否已查阅主要相关 Skill？
- 委托中的已知事实、尝试和危险行为，是否已由项目文档或实际结果核验？
- 是否已识别并如实回报所有矛盾？
- 问题边界与解释是否已有可复查依据？
- 是否已尽力满足最初委托的具体需要？
- 结论是否明确为：可直接回报，或需要进入 Issue 协商？
- **是否是行为缺陷而非文档缺失？**——文档缺失不是 Issue，应回报缺失内容，不进入 Issue 协商
- **是否需增补工具？**——需要增补工具（或主 agent 要求增加工具）时，必须进入 Issue 协商，不直接回报

任一未通过时继续调查。可直接回报时，回报后退出本流程；只有确认需要 Issue 时进入下一阶段。

## Issue 协商

**目标**：先协商 Issue，如果通过主 agent 确认，将调查确认的问题登记为 Issue，并保持未提交，等待 sandbox 接管。

**步骤**：

1. 请 invoke [[issue-lifecycle]]，并将主 agent 作为其中的用户协商；对“登记后的提交方式”使用本阶段的设置：写入 Issue 但保持未提交。

**门禁**：

- 是否已 invoke [[issue-lifecycle]]？
- 是否已将主 agent 作为其中的用户完成协商？
- Issue 是否只陈述已确认的问题，而不是调查中的推测？
- Issue 是否记录在正确项目的 `issues.md`？
- 是否已按该项目现有编号规则登记？
- 是否保持未提交，等待 sandbox 接管？
- 是否已向主 agent 回报登记结果与关联信息？

全部通过后进入候选修复。

## 候选修复

**目标**：为已登记 Issue 获得可验证的候选解决结果。

**步骤**：

1. 请 invoke [[issue-worktree-sandbox]]。
2. 将已登记 Issue 交给 sandbox，由其决定是否适合候选修复、绕过与验证方式；不重复其内部决策。
3. 接收候选结果并完成本阶段。

**门禁**：

- sandbox 是否已判断该 Issue 能否在候选环境中处理？
- sandbox 是否已按其判断执行完成？
- 原工作区中未提交的绑定 Issue 是否已清除？
- 是否已尽力满足最初委托的需要：已给出可用绕过、候选修复结果，或无法满足的明确依据？
- 是否已将结果回报？

全部通过后退出本流程。

## 禁止

- **门禁**：每个阶段逐项回答其门禁问句；任一未通过，继续当前阶段，全部通过后才进入下一阶段。
- **读取顺序**：只读取当前阶段需要的 Skill；仅在前一阶段门禁全部通过、确认进入下一阶段时，才读取下一阶段的 Skill。
